# ADD 3.0 Process Checklist

This checklist tracks the 7 steps of the Attribute-Driven Design (ADD) 3.0 methodology.

## 1. Review Inputs
- [ ] Are the primary use cases defined?
- [ ] Are the Quality Attribute Scenarios prioritized?
- [ ] Are constraints (technical, business) documented?

## 2. Establish Iteration Goal
- [ ] Is the goal of this iteration clearly stated?
- [ ] Which specific drivers are being addressed in this iteration?

## 3. Choose Elements to Refine
- [ ] Have you identified the system, sub-system, or module to focus on?
- [ ] Is the boundary of this element clear?

## 4. Choose Design Concepts
- [ ] Which Reference Architectures were considered?
- [ ] Which Deployment Patterns apply?
- [ ] Which specific Tactics (e.g., Retry, Load Balancer) satisfy the chosen quality attributes?

## 5. Instantiate Elements & Allocate Responsibilities
- [ ] Have the design concepts been mapped to concrete software components?
- [ ] Are the responsibilities of each component clear?
- [ ] Have internal and external interfaces been defined?

## 6. Sketch Views and Record Decisions
- [ ] Are there sketches/diagrams reflecting the new structural changes?
- [ ] Have ADRs been written for the major design choices made?

## 7. Perform Analysis
- [ ] Did this iteration satisfy the goal established in Step 2?
- [ ] Do any new architectural drivers emerge from these decisions?
- [ ] Should we proceed to another iteration?
